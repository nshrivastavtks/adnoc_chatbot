01 Existing Project Architecture: Unified Direct Secret Embed

How the React 19 Frontend embeds Copilot Studio directly using Direct Line Secret without external mobile token endpoints
Architecture Clarification: The "Direct Line Secret Embed" Pattern
Your implementation unifies the Embed Code and Direct Secret Key into a single direct integration. You are not using an external anonymous mobile app token URL. Instead, the React widget embeds directly into the ADNOC OASIS dashboard and uses the Direct Line Secret Key to generate short-lived JWT conversation tokens directly from Azure Bot Framework (`POST https://directline.botframework.com/v3/directline/tokens/generate`). This provides full headless control, eliminating Microsoft's rigid Web Chat iframe.
Direct Line Secret Key Embed Sequence (Zero Microsoft SDK)
1. Secret Key Session Generation
🔑

The frontend connects to Direct Line using standard HTTP `fetch`: 

POST https://directline.botframework.com/v3/directline/tokens/generate
Headers: { "Authorization": "Bearer DIRECT_LINE_SECRET" }
Response: { "token": "...", "conversationId": "...", "streamUrl": "..." }
2. Context Passing via `channelData`
🧭

Passes portal route, selected Gathering Center (GC), and user role dynamically: 

{
  "type": "message",
  "text": "What is our current alarm status?",
  "channelData": {
    "currentRoute": "/consoles/gc-3",
    "activeConsole": "GC-03",
    "userRole": "ConsoleOperator"
  }
}
3. Intelligent Thinking Filter
🧠

Uses regex heuristics (`isIntermediateMessage()`) to intercept agent progress announcements ("Let me first explore the database...") and route them into collapsible accordions.

02 Copilot Studio Tooling & The MCP Server Integration

Why connecting an MCP Server directly to Copilot Studio transforms safety, governance, and database querying
Direct Evaluation of Your Question: "What if we create an MCP Server in our app?"
Verdict: This is the optimal architecture for ADNOC.
Currently, in Screenshot 1, Copilot Studio is connected to SQL Server using generic connectors: "Get tables (V2)", "Get rows (V2)", "Execute a SQL query (V2)". Letting an LLM generate and execute raw SQL poses severe enterprise risks (accidental table drops, uncontrolled joins, performance degradation, and bypassing user-level permissions).

By building an MCP (Model Context Protocol) Server inside your app backend (Node.js/Express or Python), you can expose governed, business-specific tools (e.g., `getAlarmMetrics(gc_id, timeframe)`), allowing Claude Sonnet in Copilot Studio to execute parameterized, validated queries with 100% security!
The Governed MCP Server Architectural Pipeline
1. Eliminates Unsafe Raw SQL Execution
🛡️

In Screenshot 1, Execute a SQL query (V2) gives the bot direct query power. An MCP Server restricts the AI to predefined functions: the LLM passes structured arguments, and the server executes parameterized stored procedures.

2. Enforces Scope-Based Permissions
🔐

Addresses Feature 16 and Feature 19. When Copilot Studio invokes an MCP tool, the MCP server validates the user's active session token, ensuring operators cannot view data outside their assigned Gathering Center.

3. Seamless Connection via Modal
🔌

In Screenshot 2, configure the Add MCP server modal:
• Server URL: https://adnoc-oasis.internal/api/mcp
• Authentication: API Key or OAuth 2.0 (Entra ID).

04 Authentication, Entra ID SSO & SQL Governance

How security is enforced across React, Direct Line, and the backend MCP Server
Silent Entra ID SSO Handshake
🛡️

Without Microsoft WebChat SDK, your React application resolves OAuth challenge cards automatically: 

// In copilotService.js: Silent Token Exchange Handshake
if (activity.attachments?.[0]?.contentType === 'application/vnd.microsoft.card.oauth') {
  const sasUrl = activity.attachments[0].content.tokenPostResource?.sasUrl;
  if (sasUrl && window.msalInstance) {
    const res = await window.msalInstance.acquireTokenSilent({
      scopes: ['api://adnoc-copilot/access_as_user']
    });
    // POST token directly to Bot Framework SAS URL
    await fetch(sasUrl, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ token: res.accessToken })
    });
  }
}
Dual-Mode Security: Metadata vs Live Data
🔒

Addresses Feature 18 and Feature 20:
• Phase 1 (Metadata-Only): Copilot Studio is grounded exclusively on uploaded PDF manuals, data dictionaries, and schema definitions. No actual production operational records are shared with the LLM.
• Phase 2 (Live Business Telemetry): Enabled via MCP tools with parameterized filters once ADNOC Information Security formally approves data-sharing consent.
